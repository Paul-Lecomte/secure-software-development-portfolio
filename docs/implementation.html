Implementation

Security-related code change and compatibility notes

This page documents the implemented security improvement: a request-body size ceiling on the HTTP /path endpoint of the Python routing backend.

1. Issue addressed

PathRequestHandler._read_json() (src/http_server.py) read the request body using the client-supplied Content-Length header with no upper bound (raw = self.rfile.read(length)). A client could advertise an arbitrarily large Content-Length, causing the single-process ThreadingHTTPServer to attempt a large memory allocation — a denial-of-service vector (threat model: Denial of service; risk R1).

2. Change made

Working branch: local audit clone (C:\Users\lecom\audit-work\backend). No changes were pushed to the origin repositories.

+# Ceiling for a single JSON request body. Protects the JSON parsing path from
+# memory-exhaustion via an arbitrarily large Content-Length value.
+MAX_REQUEST_BODY_BYTES = 1024 * 1024  # 1 MiB
...
+        if length < 0:
+            self._send_json(400, {"error": "invalid_content_length"})
+            return None
+        if length > MAX_REQUEST_BODY_BYTES:
+            self._send_json(
+                413, {"error": "request_entity_too_large", "limit_bytes": MAX_REQUEST_BODY_BYTES}
+            )
+            return None
+
+        raw = self.rfile.read(length)

The constant is defined near the other HTTP defaults, and the check runs before self.rfile.read(), so oversized bodies are rejected with HTTP 413 before any allocation.

3. Compatibility risks assessed

  • Legitimate large payloads: The /path schema is small (stop IDs, timestamps, optional GPS bounding objects). A well-formed request is far below 1 MiB, so the ceiling does not affect normal operation.
  • gRPC binding: Not affected — this change is HTTP-only. gRPC has its own message-size defaults and remains a separate hardening item.
  • Status-code contract: Clients receive 413 (with limit_bytes) instead of an unhandled memory error; this is a clearer, safer failure mode.
No unrelated refactors. Only the request-size guard was added. No dependencies, algorithms, or deployment files were modified.
